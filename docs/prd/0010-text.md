# PRD-0010: Text

- **Status:** Draft
- **Author:** Federico Vezzoli
- **Created:** 2026-10-23
- **Related:** PRD-0001, PRD-0009, ADR-0004, ADR-0029, ADR-0044, ADR-0055

## Problem

Lettering is one of the most common things a hobby router cuts: signs, house numbers, names on cutting boards and gifts. Today the text has to be laid out in a drawing program, converted to paths and imported as SVG or DXF. If a word changes, the whole round trip starts again. Engraving along a line needs a single-stroke font, which most drawing programs don't offer.

## Users

- Hobbyists making signs and personalised pieces, who want to type a name and cut it.
- Small shops that repeat the same layout with different text (names, numbers).

## Goals

- A user can type a line of text, pick a font and a size, and cut it with the existing operations, without a drawing program.
- The text stays editable: changing a word keeps its place on the stock and the operations that machine it.

## Non-goals

- A full text layout engine: paragraphs, justification, wrapping in a box.
- Editing the glyph outlines, or converting fonts between formats.
- Fonts fetched from the internet at run time (the desktop app has no network, ADR-0044).
- Text on a path or an arc (a later PRD, if wanted).
- Text in a project with an STL model: a project still holds drawings or one model, never both (ADR-0055).

## Requirements

| ID | Requirement | Priority |
| --- | --- | --- |
| T1 | Add a text item to a project: its text, a font, a height (cap height, in the current units) and a horizontal alignment. It is placed like an imported drawing (PRD-0009 D1) and can be selected, resized, moved and removed like one | Must |
| T2 | Profile, pocket, engrave and V-carve operations machine a text item like any drawing. Overlapping glyphs are merged, so a pocket does not cut their overlap twice | Must |
| T3 | A text item stays parametric: it keeps its text, font, height and alignment, and its placement (position, rotation, mirroring) as settings, not as rewritten points. Editing any of them keeps the rest and the operations that machine it, in one undo step | Must |
| T4 | The app ships a few open-licence fonts, including at least one **single-stroke** font for engraving along a line. They work offline in the web and the desktop app | Must |
| T5 | Several lines of text, with line spacing | Should |
| T6 | Letter spacing | Should |
| T7 | Upload a TTF, OTF or WOFF font into a project. It is stored and exported with the project like a mesh (ADR-0029) | Could |
| T8 | Convert a text item into a plain drawing, which can then be transformed like any other but no longer edited as text | Could |

## User flow

1. In a new project, the user adds a text item, types "Rossi", picks a serif font and sets the height to 40 mm.
2. They move it to the middle of the stock and add a V-carve with a 60° bit.
3. A neighbour wants the same sign: the user changes the text to "Bianchi", and the V-carve still machines it.
4. They check the simulation and export the G-code.

## Success criteria

- A user cuts a name sign with V-carved lettering and a profile cut-out, without a drawing program and without manual G-code edits.
- A user engraves a line of text along a single stroke with a 1 mm end mill.

## Open questions

None. The app ships JetBrains Mono (monospaced, the interface's font), Arvo (serif), Pacifico (script) and Relief SingleLine CAD (single stroke), all under the SIL Open Font License (#349).
